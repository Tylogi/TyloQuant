## 范围与演进

测试集分为回归测试和持续性测试。初版只建设**正确链路的回归测试**：给定合法输入和满足要求的环境，沿用户实际使用的量化、模型导入和服务调用路径验证产物。运行服务使用应用随附的组件，不要求测试机从源码编译运行时。断网、服务重启等真实异常场景留待下一阶段，届时按实际发生频率、影响和可复现性选择用例，避免为罕见且无法稳定复现的情况增加门禁。新功能在其 PR 中附持续性测试；合入后把仍有长期价值的场景、固定输入、断言与运行条件归档进回归集。

## 初版用例结构

| 编号 | 运行层 | 输入与操作 | 必须验证的结果 |
| --- | --- | --- | --- |
| R0 | 跨平台、每个 PR | 固定的微型受支持 HF 模型 → `mfq quantize` CPU 路径 → `.mfq` → Python 普通及内存映射加载 | 命令成功；文件非空；模型配置、张量清单和必要资源齐全；两种读取方式所得关键元数据一致；不使用模拟量化或预制输出 |
| R1 | 有对应硬件的定期或指定门禁 | 同一量化产物 → 安装包提供的服务导入模型 → 固定输入生成 | 应用实际加载成功并生成可用响应；记录应用版本、模型版本和硬件；按产品支持范围判断结果 |
| R2 | 与 R1 共用环境 | 同一模型及服务 → `/v1/models`、`/v1/chat/completions` | 模型可列出，请求成功且响应格式和内容约束成立；服务可正常退出；实际请求使用安装包随附的运行组件 |
| R3 | 后续扩展 | 全精度 MFQ→量化、GGUF+配方→量化、其他已支持模型族与量化格式 | 复用 R0–R2 的断言和产物追踪，按实际支持矩阵逐项扩展，不在初版一次覆盖全部组合 |

R0 的微型模型必须具备完整配置、分词资源和运行时必需权重；现有只包含少量张量的量化单测不能直接充当 R1/R2 输入。生成断言优先检查稳定、可观察的产品行为，避免依赖随机生成的逐字文本。每个用例记录源模型版本、量化命令、应用版本、产物路径、运行条件和失败阶段，以便定位断点。

## 纳入规则

1. 新功能 PR 附上与功能对应的持续性测试，写明正向路径、输入、可观察断言和所需硬件；涉及跨环节行为时至少覆盖新增环节与相邻环节的交接。
2. 功能合入后，把稳定且仍受支持的用例归入回归层；更新用例矩阵和运行入口。只在专用硬件可跑的测试必须明确门禁方式，避免无提示跳过被当作通过。
3. 初版实施顺序为 R0 → 用安装包导入同一产物并生成内容 → 经服务接口验证模型列表与请求响应。先跑通用户实际路径，再扩充模型与格式组合。源码编译仅在明确测试构建或发布流程时单独处理。
