# MI300X TQ validation, 2026-10-24

The HIP path accepts the existing RTRELL05 TQ payload with independent 1–8 bit
rows, subgroup scales or shared column scales, and padded logical widths.
Quantization retains the complete 16-bit state space. The default shared-column
search includes upstream zero-clipping scales, sparse scale repair and FP16
path-cost overflow protection, using the optimized HIP encoder.

## Quantization

Qwen3.5-4B, all 248 text projection matrices at every precision from 1 through
8 bits: 1,984 saved payloads and 28.553 billion fitted weight candidates.
Seven MI300X devices, separate worker processes, `search="fast"` and shared
column scales. Both measured runs used compiled kernels and fresh output
directories; no candidates were resumed. Time includes worker startup, source
loading, fitting, packing and payload writes. Calibration data collection and
assembly of a full MFQ model are separate operations.

| Search policy | Seconds | Million weight candidates/s |
|---|---:|---:|
| Previous sampled column search | 60.43 | 472.52 |
| Upstream zero-clipping search with HIP fast dispatch | 61.51 | 464.19 |

The updated policy took 1.8% longer in this paired measurement. A retained upstream
reference-policy comparison uses the same encoder and checks exact states
and anchors for all bit widths, fast/adaptive modes and clipping modes.

## Native inference

Qwen3.5-4B, one MI300X, FP16 KV cache, 256 generated tokens, three measured
samples after warmup. TQ uses mixed row precisions and its dynamic row kernels;
Q8 activations and MTP are disabled. TQ prefill chunks contain 8,192 tokens.
The llama.cpp comparison uses Q4_K_M, batch 2,048 and microbatch 512. PP measures
the full prompt; TG measures decoding after that prompt.

| Prompt tokens | TQ PP tokens/s | llama.cpp PP tokens/s | TQ TG tokens/s | llama.cpp TG tokens/s |
|---:|---:|---:|---:|---:|
| 2,048 | 12,340 | 12,423 | 246.8 | 245.1 |
| 8,192 | 13,769 | 12,247 | 242.0 | 236.8 |
| 16,384 | 13,202 | 11,746 | 233.9 | 226.0 |
| 32,768 | 11,933 | 10,898 | 224.2 | 217.2 |
| 65,536 | 10,088 | 9,526 | 206.9 | 199.6 |

The TQ model is a deterministic mixed-precision speed fixture matched to the
base projection byte budgets. These timings do not establish matched model
quality: the two formats, weight values and benchmark harnesses differ. The
fixture was assembled before the latest zero-clipping search update. Native
inference kernels and its saved weights were unchanged by that search update.

## Reproduction tools

`bench/tq_hip_checkpoint.py` saves independent candidates and validates the
source hash, search configuration, quantizer revision and payload hash before
resuming. `bench/tq_hip_multiprocess.py` distributes disjoint matrix shards.
`bench/tq_hip_model.py` assembles a byte-budget speed fixture from a candidate
bank. `bench/tq_hip_model_bench.py` retains complete fixed-token PP/TG requests.
Each accepts explicit input/output paths; models and candidate banks are kept
outside version control.

`bench/check_tq_hip_runner.py --output PATH` uses deterministic synthetic
weights to verify resume, quantizer-change invalidation, optional output
failures and required compute failures. Native regression fixtures are small
synthetic RTRELL05 payloads checked against independent CPU reconstruction.
